## [Unreleased]

### Fixed

- A DLL loaded in Inventor whose metadata the C# compiler cannot read (for example a protected assembly from another add-in) no longer makes every `inventor_send_code` compile, and so every script baked tool, fail with `CS0009`. The file is left out of the compile references; the response then includes `skipped_references` (`name`, `reason`) and compile errors list the skipped names. Same fix as rvt-mcp [#38](https://github.com/bimwright/rvt-mcp/issues/38).
- `inventor_export_drawing` to PDF of every sheet in document order (none excluded from printing) translates the source drawing directly instead of copying each sheet into a hidden template drawing with `Sheet.CopyTo`, which killed Inventor 2027 on a 5-sheet drawing. Subsets, reordered sheets and per-sheet DWG still use the sheet copy. Each file row reports `export_strategy` (`direct`, `copy_sheets` or `save_as`).
- The gateway call log keeps the error code and message of tools answered by the server alone (for example an export path refused by the output-root policy); they were logged with `error_code: null` and the result's `error.code` hashed like a script body.
- `inventor_send_code` `data` reaches the script as sent. ISO date-time strings stay strings (they became dates and came back in another format and offset), integers stay exact, and other numbers must be finite doubles: `1e400` and `NaN` are rejected with `INVALID_ARGUMENT` instead of arriving as the string `"Infinity"` or dropping the request; duplicate keys are rejected too. The server sends the data as JSON text (`data_json`) and `data_hash` covers that text, so equal hashes mean the script received equal data. The same rules apply to the `paramsJson` of script baked tools. Update the server and the add-in together: an older add-in does not read `data_json`, so a script that uses `data` fails to compile there instead of receiving changed values; a new add-in still accepts `data` from an older server.
- ISO date-time strings in any tool argument (for example an iProperty value) reach the add-in handler unchanged instead of being converted to the machine's time zone and re-formatted.
- iPart assembly failures preserve the committed mutation state in their recovery receipt and reuse the verified member signature without extra COM reads after commit.
- Call journals rotate and retain files under bounded storage policies; transport shutdown closes active I/O, descriptor publication follows listener readiness, and queued STA work has bounded admission and cancellation before execution.
- Positional dimensions distinguish an actual parent transaction from Inventor's unidentified idle transaction, allowing existing parts to be edited while preserving cross-document transaction checks and rollback receipts.
- iLogic rule source is redacted like `send_code` bodies: journals and History record only its hash and length (unless body caching is opted in), and History disables re-run for redacted iLogic entries.
- When restoring the sheet thickness fails, `set_sheet_fabrication_thickness` returns `rollback_failed` with an unknown mutation state, so `batch_execute` with `continue_on_error=true` stops instead of committing an uncertain step.
- Sketch, feature and sheet fabrication tool errors forward the handler's response data, so restored/unknown mutation receipts from dimension, revolve, batch and thickness calls reach the client.

### Added

- `HOST_BUSY` (bimwright family contract FC-BUSY): while a modal dialog is open in Inventor, every command except health is refused at once with `HOST_BUSY` and the dialog's caption, instead of queueing behind the dialog until `TIMEOUT`. The add-in checks again on Inventor's main thread, so a dialog's message loop cannot run a queued command. A full command queue (was `API_ERROR`) and a command that expired before it started (was `TIMEOUT`) also return `HOST_BUSY`. Each says the command was not started and will not run later. `TIMEOUT` now only means a started command whose outcome is unknown. `inventor_health` adds `host_busy` and `busy_reason`.
- `inventor_new_drawing`, `inventor_add_sheet` and `inventor_set_title_block` run under `Application.SilentOperation`, so a template whose title block has prompted entries no longer blocks `new_drawing` on the "Prompted Texts" dialog until `TIMEOUT`.
- Document confirmation before writes (`document_target_v1`, bimwright family contract; rvt-mcp/dwg-mcp parity). `inventor_switch_target(target, verify=true)` confirms the document active in that Inventor. Until then writes return `TARGET_UNCONFIRMED` and are not sent, even with one Inventor open; reads are unaffected. Right before a write runs, the add-in checks on Inventor's thread that the confirmed document is still active, else `DOCUMENT_CHANGED` (or `DOCUMENT_UNCONFIRMED`) and the command is not started. A write with an explicit `document` parameter names its own target and skips that check. Opening or creating a document (`open_document(s)`, `new_part`, `new_assembly`, `new_drawing`, `new_sheet_fabrication_part`, `create_part`) moves the confirmation to the document it activates, unless another document had become active before the call. `inventor_get_current_target` and `inventor_switch_target` report `document_confirmed`, `confirmed_document_id` and `confirmed_document_title`. Document ids last until Inventor closes the document; reopening it gives a new id. `send_code` with `compile_only` and baked-tool installs are not document writes.
- `PAIRING_REQUIRED`: writes between a server and an add-in that do not both support `document_target_v1` are refused before they run, in both directions; reads and health still work. **Update the server and the add-in together** and restart Inventor and the MCP client.
- `inventor_send_code` `result_contract="task_v1"` (rvt-mcp parity; default `"legacy"` is unchanged): the script returns `McpTaskResult.Pass(value)` or `McpTaskResult.Fail(code, message, details)`, imported automatically. The response carries `_task` (`contract`, `status` `passed`/`failed`/`not_reported`, `error{code, message}`); `Fail` sets `ok=false` with `error` `"<code>: <message>"` and returns the details as `result`, and a script that returns no `McpTaskResult` fails with `TASK_RESULT_REQUIRED`. A failed task does not undo edits the script already made. Legacy results that report `passed`, `ok` or `success` `false` get an advisory `task_contract_hint`. `task_v1` calls are not observed for adaptive bake. Update the server and the add-in together: an older add-in does not import `McpTaskResult`, so a `task_v1` script fails to compile there.
- `HOST_CRASHED`: when the add-in closes the connection without answering and the Inventor process is gone within 5 seconds, the call returns `HOST_CRASHED` instead of `TARGET_UNAVAILABLE`, says that edits since the last save are lost and where Inventor writes its crash files, and asks the agent not to resend. If Inventor is still running the code stays `TARGET_UNAVAILABLE`. Both messages name the target the call went to.
- Crash breadcrumb: while the call log is on, the add-in writes `inflight-<pid>.json` (tool, request id, start time, session id and log-safe params; `send_code` only as hash and length) next to `mcp-calls.jsonl` before a command runs on Inventor's thread and deletes it when the command returns. If Inventor dies inside the command, the next add-in start turns the leftover marker into a `crash_suspected` line in `mcp-calls.jsonl` under the original session id, so the command that ended Inventor is no longer missing from the journal.
- ToolBaker script tools: a `send_code` script that takes its inputs as `data` can be baked into a tool and then called with only the data, `inventor_run_baked_tool(name, paramsJson=<data>)`. With adaptive bake on (`--enable-adaptive-bake`, off by default), each `send_code` call with `data` records only two hashes (script, data); when one script has succeeded with 3 different data inputs within 10 days, a suggestion opens and the response carries a `bake_hint`. `inventor_accept_bake_suggestion` takes the same `code` and `modules`, checks them against the recorded hash and stores the script only then. A script tool runs as `send_code` and is refused wherever `send_code` is disabled or the connection is read-only; preset and macro tools keep the read-only dispatch allow-list. A `send_code` call that matches an accepted script tool gets a `bake_hint` pointing at it. Usage events no longer fail on an empty session id.
- `inventor_build_solids` (feature toolset) builds many extruded solids in an existing part in one call, from data instead of a C# script: `items=[{name, op?: new|join|cut, target?, box|tube|prism|extrude}]` (max 1000), lengths in mm. `box` takes min/max corners; `tube` takes end points, outer diameter and optional wall; `prism` extrudes a profile along x, y or z between two coordinates; `extrude` takes a plane pose, signed depth and profile. Profiles use the `inventor_create_part` shape syntax. Join and cut items may omit `name` (they create no body; the feature is named `<op>_<index>`), and `defaults={tube: {od: 48.3}, ...}` fills shape keys that items leave out, so repeated values are written once. All items are validated before Inventor is touched (degenerate sizes, self-crossing or touching loops, holes outside their loop, duplicate names, targets that are not bodies) and every problem is returned at once. After building, each item must give a healthy feature; a new item must add exactly one body, which is named after the item; a join must add volume and a cut must remove it. A failing item's objects are removed and the build stops (`stop_on_error=false` continues); built items are kept and the error carries `next_index`. `dry_run=true` validates against the part. The build is one undo step. `inventor_send_code` scripts that extrude sketched profiles get a routing hint to this tool.
- `inventor_export_bodies_sat` (export toolset) writes solid bodies one ACIS SAT file per body, across many part documents already in memory, in one call: `items=[{document, bodies?, key?}]` (max 200 items / 2000 bodies), files `<out_dir>\<key>-bNNN.sat`. Documents, body refs, output paths (allowed output roots) and existing files are checked before the first write; `overwrite=true` replaces files. `verify=true` (default) reads each file back and compares body count, face count, volume and bounding box. A failing body is reported and the rest continue. The response is a compact summary (counts, maximum verify errors, failing bodies); `detail=true` adds one row per body. `inventor_send_code` scripts calling `DataIO.WriteDataToFile` get a routing hint to this tool.
- Eight `ipart` MCP tools support managed Standard iPart factory copies, typed table rows, row selection, verified member generation, one-way saved Excel catalogs and assembly occurrence placement/switching. Parameter, material, Part Number, Description and feature-suppression columns are supported. Preview-first table/catalog/generation operations, persistent checkpoints, stale-member detection and explicit partial-file recovery keep library sources separate from generated copies. Custom iParts, sheet metal, existing-factory adoption and iAssemblies remain outside this scope.
- `inventor_list_sketch_points` discovers document-scoped sketch point references, centres, endpoints and the origin without changing geometry. `inventor_add_sketch_point_dimension` creates horizontal, vertical or aligned driving distances between these references, with numeric mm or parameter expressions, explicit document targeting, recompute/geometry verification and transactional rollback.
- Native Excel parameter link/list/reload tools for local `.xlsx` workbooks: saved-value preflight, stable table IDs, recompute/readback checks, persisted change checkpoints and explicit recovery receipts for spreadsheet-cache changes that survive transaction abort. Excel mutations are excluded from `batch_execute`.
- `inventor_add_sketch_dimension` and `inventor_revolve` accept parameter expressions as well as numeric inputs, based on a contribution by `gavinmcutler`. Line dimensions drive length; circles/arcs drive radius. Expression parameters remain linked when source parameters change. Bare numeric strings use mm/degrees; unitless compound expressions use document units. Dimension values must be positive; expression revolve angles must evaluate to more than 0 and at most 360 degrees. Numeric revolve angles retain their existing full/reverse behavior.
- Dimension and revolve creation validate expressions, verify recompute/readback, and abort their own transaction on failure. Inside `batch_execute`, failed operations roll back without discarding successful steps when `continue_on_error=true`; an uncertain rollback stops further batch writes and forces rollback. Responses do not claim restoration if transaction abort itself fails.
- Sheet fabrication tools (`sheet_fabrication` and `sheet_fabrication_query` toolsets): `inventor_new_sheet_fabrication_part` (explicit template, or the first localized `*Sheet Metal*.ipt`), `inventor_sheet_fabrication_info` (read-only: thickness, bend radius, style, unfold method, bend count, flat blank size), `inventor_set_sheet_fabrication_thickness` (mm or expression, overrides the style), `inventor_sheet_fabrication_face`, `inventor_sheet_fabrication_flange` (height read back and rewritten once if Inventor drops it), `inventor_sheet_fabrication_cut` (across bends, normal to flat) and `inventor_flat_pattern` (creates it if missing, reports the blank size for `export_dxf source=flat_pattern`). `inventor_unwrap_try` trial-unwraps faces of any part into a surface body, measures it and rolls back unless `keep=true`.
- `inventor_list_faces` and `inventor_list_edges` (read-only, `query`): faces with surface type, area, bbox and planar normal; edges with curve type, length and radius. Their `body:B/face:F` and `body:B/edge:E` ids feed fillet, chamfer, work features, flanges and `unwrap_try`. Both filter by body and type and cap output with `max_items`.
- iLogic tools (`ilogic` toolset): `inventor_ilogic_list_rules`, `inventor_ilogic_get_rule` and `inventor_ilogic_read_log` (read-only), and `inventor_ilogic_run_rule` / `inventor_ilogic_run_external_rule` with flat `arguments` passed as a NameValueMap. Rule errors are returned in `exceptions[]` from iLogic's RuleExceptionsLog, because the file log depends on `iLogicLogger.config` and is often empty. `inventor_ilogic_upsert_rule` and `inventor_ilogic_run_snippet` sit in the `code` toolset under the `send_code` gate; a snippet runs as a temporary rule that is always deleted and returns its result through the custom iProperty `MCP_RESULT`, which is restored afterwards. Rule side effects are not rolled back. Hosts without iLogic return `UNSUPPORTED_HOST`.
- `inventor_list_commands` (read-only) lists Inventor control definitions; `inventor_run_command` executes one by internal name (`silent=true` answers prompts with defaults); `inventor_undo` undoes 1–20 steps on the active document.

### Changed

- Tool surface is now 146 tools by default (`--toolsets all`), 140 with `--disable-send-code` and 38 with `--read-only` (v0.2.1: 111 / 107 / 28). The README read-only permission allowlists and `docs/testing/readonly-tools.json` list all 38 read-only tools.
- The iLogic run, `run_command` and `export_bodies_sat` descriptions state that their effects are not rolled back (replaced SAT files are not restored).
- `inventor_send_code` accepts `data` (any JSON, max 512 KiB), which the script sees as the variable `data` (`JToken`; `Newtonsoft.Json.Linq` is imported), so coordinates, paths, member lists and expected values no longer have to be inlined into source. Without `data` nothing is added, so existing scripts that declare their own `data` variable keep working. `compile_only=true` compiles the script and its modules without running it or touching the document. Scripts over 4000 characters without `data` or modules get an advisory `size_hint`. Call logs record only the data hash and length; History re-run replays the code without the original `data` unless `BIMWRIGHT_CACHE_SEND_CODE_BODIES=1` keeps the whole call in memory.
- `inventor_send_code` can return one advisory `routing_hint` pointing to an available typed tool, on success or failure. Scripts using saved modules receive no routing hint; execution and script results are unchanged. Its description and server instructions include a compact task-to-tool guide.
- Target selection no longer guesses between Inventor sessions (rvt-mcp #19 parity). With several live sessions and no selection, calls return `AMBIGUOUS_TARGET` with candidates instead of using the most recent heartbeat. A selected session is kept by pid and process start time; when it exits or its pid is reused, calls return `TARGET_LOST` instead of silently moving to another Inventor. `inventor_switch_target` accepts `pid:<n>` and `id:<target_id>`, refuses selectors that match several sessions and keeps the current selection on failure. `--target <year>` now selects that year instead of falling back to the first live target. `inventor_list_available_targets` marks the selected target and `inventor_get_current_target` reports how it was selected.
- Input schemas publish empty objects instead of bare `true` schema nodes for client compatibility. Boolean defaults, examples, object-openness policies and native argument handling are preserved.
- `inventor_health` reports loaded server/plugin identities and separate `update.components` statuses against one stable release. Startup requests `check_updates=true` once; routine probes remain offline. Notification codes distinguish newer releases, mismatched/unverified evidence, unavailable external lookup and informational `LOCAL_VERSION_AHEAD`. Messages report lookup/protection reasons without implying a local fault. `identity_observed`/`unobserved_components` separate missing runtime observation from protected observed builds. `update_guidance.mode` returns installation steps and installation-authorization requirements only for a permitted `prepare_update` proposal; offline, failed lookup and review modes contain no installer commands. Semantic update flags do not prove release identity. No target preserves server identity with a failed host probe; health never downloads or installs packages.
- Initialization includes the full gateway informational version; the health tool's catalog metadata and `client_verification` support same-connection reconnect verification. The server cannot prove the client discarded cached handshake/catalog data. Runtime assembly version/MVID are separated from capture-time disk hash observations; source revision equality does not verify published artifact bytes or publisher trust.
- Updated the English, Vietnamese, Japanese and Simplified Chinese health documentation with component statuses, notifications, safe update proposal guards and client-verification limits.
- The agent install guide gates updates on a permitted health proposal, keeps its exact release tag and verifies the companion ZIP checksum before extraction and the required manifest before installer preview. Health guidance distinguishes external tag-resolution failures and mixed ahead/unobserved component states without treating them as local faults or stopping otherwise healthy Inventor work.

## [0.2.1] - 2026-10-02

### Changed

- Full mode now exposes all 111 tools by default, including code tools. `--disable-send-code` leaves 107 tools; the add-in kill switch is `BIMWRIGHT_INVENTOR_PLUGIN_DISABLE_SEND_CODE=1`.
- Read-only registration follows explicit per-tool annotations: 28 tools remain, including parameter/property queries, view fit and code-module listing. Inspecting ToolBaker no longer creates or migrates a database.
- Tool-call files are off by default on both sides. `--enable-call-log` / `--disable-call-log` control recording; code and nested module bodies become length/hash metadata. In-memory History remains available.
- `send_code` exposes nullable `doc` and wraps the active document in one Inventor transaction. Runtime/host errors abort that transaction; warnings are returned. Other documents, lifecycle operations and file writes remain outside its rollback scope.
- Every tool carries activity metadata and explicit permission hints, except unannotated `send_code`. Server-only calls also report to the selected host's toast/History when available.
- Oversized script responses carry a spill schema, preview, unknown mutation state and a no-replay warning. Invalid spill retention falls back to 36 hours. The final response guard recognizes every read tool.

### Fixed

- Explicit code-module storage rejects credential-like source before compile/save, rather than persisting sensitive constants or silently rewriting code.

- Added setup ZIP SHA-256 sidecars, NuGet README metadata, synchronized permission lists and a public host-free per-tool MCP contract test.
- Toast regression positioning respects the monitor work area; fallback summaries show a readable operation name.
- Top-corner toast cards now clear the title bar and ribbon tabs by the same 56 DIP gap as RVT; bottom corners keep their existing placement.
- Toasts identify document reads without claiming a save, show document/material/unit results, and summarize multi-image captures with the latest available thumbnail. Structured drawing and ToolBaker errors retain their message and code in toast and History.
- MCP initialization instructions now describe default-on `send_code`, its disable flag, read-only/toolset filtering and the optional host kill switch.


### Added

- **Drawing Phase 2.** Typed tools add attached notes and symbols, custom tables, annotation/table edits, explicit item deletion, document drawing styles, and sheet editing. Operations report native readback and preserve the accepted Inventor 2027 fixture scope and documented exclusions; see [Phase 2 coverage](docs/testing/drawing-phase2.md).
- **Drawing Phase 3.** `inventor_create_design_view`, `inventor_find_view_geometry`, `inventor_sketch_on_view`, and `inventor_hide_view_edges` add scoped design views, drawing-geometry discovery, drawing-view sketches and native edge visibility control. See [Phase 3 behavior and limitations](docs/testing/drawing-phase3.md). These earlier live records do not establish v0.2.1 runtime or client acceptance.
- **RVT toast parity.** Deliberate hover opens a virtualized three-row activity timeline with sanitized outcome/time/duration tooltips, live-tail and animated arrivals. Status adds four owner-relative corners, opt-in title-row drag, saved offsets and Reset position. Expansion keeps the anchored edge and respects reduced motion; Inventor retains its dedicated toast thread and unowned window.
- **Drawing Phase 1 (Inventor 2027, supported scope accepted).** Eleven typed tools cover drawing inspection, unsaved template creation, sheets/title blocks, base/projected/arbitrary/detail/section views, edits, attached dimensions and supplied symbol balloons, PDF/DWG/IDW exports and PNG capture. Drawing writes are excluded from read-only and `batch_execute`; matching managed creates reuse persistent names/signatures. Atomic batches preflight inputs and report rollback outcomes. Cold inactive sheets report unavailable annotation data, and annotation writes/shaded rebuilds reject that state before mutation. See [coverage and release dependencies](docs/testing/drawing-phase1.md); crop, native BOM balloons, hidden-loaded capture and dependency-preserving shaded rebuild remain explicitly deferred.
- Drawing metadata carries tool names, toolset, short descriptions and actual timeouts into toast/history summaries. Large completed drawing writes retain compact effect summaries. Spill retention defaults to 36 hours, is configurable, and never removes younger files to meet a count cap.
- The response policy now runs once at the final MCP result, including server-only validation/results. UTF-8 warnings default to 64/256 KiB with a 1 MiB budget. CLI/JSON/environment settings support custom thresholds and guard-off; independent transport limits remain active. Oversized reads request narrowing; completed writes preserve bounded effects and require readback instead of replay.

- **Fewer send_code round-trips (cycle 2).** Typed tools for the jobs agents most often had to script, aiming to cut `send_code` use by about 60% (tool surface 84 default / 88 with send_code):
  - `inventor_create_part` — a whole part from a JSON recipe (sketch rect/circle/polyline-with-bulges and inner voids on origin or fixed planes → extrude / hole / fillet / chamfer → material + iProperties → silent Save-As), `dry_run`, errors that name the recipe path, and an unsaved close when a step fails.
  - Occurrence selector shared by the bulk assembly tools (`names` globs, `regex`, `file`, `path_contains`, `leaf`, `max_depth`, `include_suppressed`, `limit`; zero or too many matches is an error with the closest names). New `inventor_list_occurrences` (fields incl. bbox, transform, material, appearance, mass, volume; inline or file), `inventor_place_occurrences` (poses as origin+rotation, axes or matrix; `lock=workplanes` holds a pose with three fixed work planes, like the helper scripts did), `inventor_delete_occurrences`, `inventor_set_occurrence_state`, `inventor_set_appearance` / `inventor_reset_appearance`.
  - `inventor_check_interference` takes `set_a` × `set_b` selectors with a bounding-box prefilter and `max_pairs`; `inventor_measure_min_distance` takes `pairs[]` or `set_a` × `set_b` with `threshold_mm`. Both stay backward compatible.
  - `inventor_set_view_state` (design view, object visibility, occurrence visibility); `inventor_capture_view` accepts the same keys plus orientation/camera/fit and `shots[]` for several images in one call.
  - `inventor_save_all`, `inventor_open_documents`, `inventor_close_documents`.
  - Optional `document` parameter (path or name of an open or referenced document, never auto-opened) on `get_document_info`, `list_bodies`, `list_features`, the iProperty / parameter / material / mass tools, `save_document` and `close_document`; `get_document_info(references=true)` returns file references; `list_open_documents` reports `dirty`/`visible` and filters.
- **Code modules for send_code:** `inventor_save_code_module` / `inventor_list_code_modules` / `inventor_delete_code_module` and `inventor_send_code(modules=[…])`. Modules are policy-checked and dry-compiled in the add-in before they are stored; diagnostics and runtime failures name `module:<name>` or `script` and the line; responses echo module hashes.
- **send_code diagnostics:** structured `diagnostics[{source, line, column, code, message, hint}]` for compile errors and `location{source, line, text}` for runtime exceptions, with repair hints from an embedded rule table (`send-code-hints.json`, 48 rules for common COM-interop mistakes). `result` values above 64 KiB spill to a file like stdout. `silent=true` runs a script under `Application.SilentOperation`.
- **Call journal v3:** every server journal line carries `client_name` / `client_version` from the MCP handshake; send_code start lines record `timeout_ms`, `silent` and module names/hashes; `save_code_module` records the module code once. Finish lines carry the returned data as `result` (masked, capped at 64 KiB), and tools answered by the server alone (code modules, ToolBaker DB) are journaled too.
- **Installer rework (rvt-mcp v0.6.3 parity).** `install.ps1` now installs the server to the fixed path `%LOCALAPPDATA%\Bimwright\ipt-mcp\server\current\ipt-mcp.exe` — MCP clients are configured once and an update only replaces the files behind that path. Every replacement is recorded and rolled back on error (bundle backups are full copies; a locked file inside the bundle aborts the swap before anything changes; a server copy an MCP client still runs is renamed aside and kept whole, then swept once free). The installer validates `manifest.json` checksums and the bundle payload (parseable `PackageContents.xml`, only our ClientIds, assemblies present) before touching the machine, refuses to run while Inventor is open, blocks on a machine-wide manifest carrying our ClientId under `%ProgramData%`, removes stray per-user `.addin` manifests with our ClientIds, byte-verifies the installed bundle against the package, unblocks downloaded files (MOTW), and smoke-checks the server with `ipt-mcp.exe --help`. It never reads or edits MCP client configs. `-Uninstall` removes only the bundle/stray manifests; `-PruneOldServers` retires legacy `server\<version>\` copies after clients are repointed.
- **`uninstall-all.ps1`** (packaged as both `uninstall.ps1` and `uninstall-all.ps1`): delete-list sweep — bundle, legacy `Bimwright.Ipt.Server` global tool, server copies, `inventor-YYYY-PID.json` discovery files and the spill cache — while keeping settings, ToolBaker data, journals, logs, captures and anything unrecognized. `-Purge` deletes the whole tree plus the sibling `ipt-mcp-calls*.jsonl`; `-KeepLogs` preserves logs during purge; `-WhatIf` previews; in-use server copies are kept whole and reported; failures exit 1.
- **`AGENTS.md` install guide** shipped inside the setup ZIP: machine-readable agent instructions covering the fixed server path, the two approval gates, per-client wiring contract (`ipt-mcp` entry → `server\current\ipt-mcp.exe`), verification and rollback.
- **Plugin version stamping:** all six plugin shells now carry `<Version>`, so add-in DLLs report a real FileVersion/ProductVersion instead of `0.0.0.0`.
- **MCP `serverInfo` metadata:** the server answers the MCP handshake with name `ipt-mcp`, title, description, website URL, and a version derived from `AssemblyInformationalVersion` (git-suffix stripped) — no more hardcoded version. `ipt-mcp.exe --help` / `-h` prints usage and exits 0 before any transport or config work, which is what the installer's smoke check runs.
- **Installer regression suite** (`tests/installer/`): sandboxed upgrade/rollback/verification tests and uninstall sweep tests run on both Windows PowerShell 5.1 and PowerShell 7 in CI, with result JSON uploaded as artifacts.
- **Single activity card (rvt-mcp parity, Inventor host kept).** Command results update one compact card with rolling Success / Failed / Capture counters instead of a stack of up to three toasts. The card idles for 20 seconds after the latest result; a real hover pauses and leaving rearms the full interval. A stationary cursor under a card that just appeared is not a hover. Clicking the card opens History and dismisses it; × only dismisses. The card title names the gateway and the Inventor year (`ipt-mcp 2027`). Read and write share the blue accent; the first failure keeps the accent red until the card closes. Captures, including inline `capture_view`, are a subset of successes. A saved capture also shows a thumbnail; there is no per-tool queue. The dedicated STA and the unowned no-activate window stay Inventor-specific; the card itself is the shared rvt-mcp / dwg-mcp window, with one fixed light style.
- **Toast branding is session-only and off by default.** Ribbon **Toast Brand** is not written to config and is disabled while toasts are off, keeping its pressed state. With it on, a real hover reveals the BIMwright wordmark after 100 ms (one 500 ms wipe, letters settle at 0.8) and fades it over 200 ms on leave. The card does not wipe the wordmark when it appears. Ribbon **Bimwright ▸ MCP → Toasts** persists `enableToast` in `%LOCALAPPDATA%\Bimwright\ipt-mcp\iptmcp.config.json` (default on); `BIMWRIGHT_INVENTOR_ENABLE_TOAST` overrides the file. **Status** opens the diagnostic dialog.

Re-run re-executes a live entry through `InventorStaDispatcher` and diffs numeric result fields against the original; historical and params-truncated entries are view-only. Privacy matches rvt-mcp: `send_code` bodies are redacted to `{code_hash, code_length}` unless `BIMWRIGHT_CACHE_SEND_CODE_BODIES=1`, and `BIMWRIGHT_PERSIST_SEND_CODE_BODIES` (+ `BIMWRIGHT_PERSIST_SEND_CODE_BODIES_TTL`, default 4 h) keeps bake-redacted bodies in `send-code-journal.jsonl` so re-run can recover them — the window warns that a recovered body is redacted and may behave differently.

- `derive_envelope` can no longer run inside `inventor_batch_execute`: it creates and activates a new document mid-transaction, so later steps would edit the new document while the transaction belongs to the old one — it's blocked alongside the other document-lifecycle commands (external review finding).

- `derive_envelope` actually supports `.iam` sources now via `DerivedAssemblyComponents` (per-occurrence inclusion, `bounding_box` → `kDerivedBoundingBox` + `RemoveInternalVoids`); `include_bodies` is rejected for `.iam` with a clear error, and the response carries `source_type` + `occurrences`.
- `inventor_list_iproperty_sets` gained `max_items` (default 200, counting total properties across sets) plus `truncated`/`properties_total` and per-set `properties_omitted`, so a large custom-property set can be narrowed instead of tripping `RESPONSE_TOO_LARGE`.
- The call journal no longer persists raw secrets: `ServerLogger` deep-masks params before writing (credential-named keys replaced wholesale, every string value swept by `SecretMasker`), and `error`/`data_error` on finish lines pass through `ErrorSanitizer`. `SecretMasker` additionally covers `Bearer <token>` and key=value/key:"value" secrets (`password`, `api_key`, `authorization`, token family) in code strings — honoring the SECURITY.md promise.
- Spill files and `results_preview` are sanitized BEFORE being written: `ResponseSpillWriter.AttachResults` runs the same error/message-field sanitization the dispatcher applies (now shared as `ErrorSanitizer.SanitizeErrorFields`) plus a `SecretMasker` pass over the serialized payload — previously a batch step error could persist raw paths/secrets to the 24 h spill file.

### Added

- **MCP server** (`Bimwright.Ipt.Server`, .NET 8 console, stdio transport,
  `ModelContextProtocol` 1.1.0). Single process, independent of the Inventor version; compiles

  - Each add-in implements `ApplicationAddInServer`, carries a unique `[Guid]` ClientId that

    the `SupportedSoftwareVersion` brackets (internal major = calendar year − 1996).

  created on Inventor's main thread during `Activate` (Inventor has no `ExternalEvent`). Every
  command runs on the UI thread through `Control.BeginInvoke`.

  `PipeTransportServer`, NDJSON framing, auth-token verification, response-size guard, and
  per-instance discovery descriptors at
  `%LOCALAPPDATA%\Bimwright\ipt-mcp\inventor-<year>-<pid>.json`. The server enumerates live
  targets and drops dead/stale ones (dead PID, expired heartbeat, wrong host app, out-of-range year).
- **46 Phase-1 tools** (MCP names prefixed `inventor_`):
  - 3 server-side **meta/target** tools (`list_available_targets`, `get_current_target`,
    `switch_target`).
  - **Query/document**: list open documents, document info, new part/assembly, open/save/close,
    set units, set material.
  - **Parameters / iProperties / mass**: list/get/set/create parameter, get/set iProperty,
    mass properties.
  - **Sketch**: create sketch, project geometry, draw line/circle/rectangle/arc, sketch
    dimension/constraint, close sketch.
  - **Feature / work geometry**: extrude, revolve, fillet, chamfer, work plane, work axis.
  - **View / export**: capture view (bounded base64 PNG), export STEP / STL / DXF.
  - `inventor_send_code` (Roslyn C# scripting against `Inventor.Application`) — opt-in only.
  - 6 **ToolBaker** tools (3 read-only + 3 write) for proposing/accepting compiled query tools.
- **Read-only mode** (`--read-only`): removes every write-capable toolset
  (`document, parameters, properties, sketch, feature, export, code, toolbaker_write`) while
  keeping `meta`, `query`, read-only `toolbaker`, and `inventor_switch_target`. The add-in
  `CommandDispatcher` enforces it as a second line of defense (`READ_ONLY`).
- **send_code opt-in gate**: OFF by default; requires `--enable-send-code` on the server **and**
  `BIMWRIGHT_INVENTOR_PLUGIN_ENABLE_SEND_CODE=1` in the add-in. Otherwise `SEND_CODE_DISABLED`.
- **Progressive disclosure**: `--toolsets a,b` and a keyword-dense `ServerInstructions` so weak
  models and MCP Tool Search only see the enabled surface.
- **Units boundary**: every length input is converted mm→cm and every length output cm→mm
  (Inventor's API uses internal centimetres), centralized in `shared/Handlers/UnitConvert.cs`.
- **Error model** (`InventorErrorCodes`): `NO_TARGET, TARGET_UNAVAILABLE, NO_DOCUMENT,
  WRONG_DOCUMENT_TYPE, INVALID_ARGUMENT, UNSUPPORTED_HOST, API_ERROR, TIMEOUT,
  RESPONSE_TOO_LARGE, READ_ONLY, SEND_CODE_DISABLED, UNAUTHORIZED`.
- **Server-only test suite** (xUnit, .NET 8): registration / read-only / toolset filtering,
  envelope round-trip, response-size guard, target-registry stale-cleanup, transport selection,
  TFM-split matrix, send-code-disabled, ToolBaker dispatch authorization, DTO validation, and
  `.addin` manifest invariants (ClassId==ClientId, assembly name, single-version brackets).
- **Packaging**: `scripts/package-bundle.ps1` assembles the per-user, registry-free
  `%APPDATA%\Autodesk\ApplicationPlugins\Bimwright.Ipt.bundle\` layout (a `PackageContents.xml`
  entry point plus per-version subfolders with the built DLL + `.addin`). Supports `-DryRun`.

### Known limitations

- **Not validated against a running Inventor.** This build box has no runnable `Inventor.exe`
  (and only the 2025-2027 interop assemblies, with the 2026/2027 ones being stubs). All
  Inventor-API handler bodies are compile-only until the manual smoke run on a real Inventor box
  (`docs/testing/manual-smoke.md`). Do not treat this as production-ready before that passes.
- The generated `PackageContents.xml` and the `.addin` element schema are **best-effort** and
  must be verified against the installed Inventor SDK before release (see the packaging script's
  output and the FLAG comments in `scripts/package-bundle.ps1`).
- Autodesk Inventor binaries / SDK / interop assemblies are **not** redistributed with this repo.
